# A small fMRI task in PsychoPy

Build a tilt discrimination task, then inspect how the design becomes stimuli, responses and event times.

## Start in Builder

1. Open **PsychoPy Standalone 2026.2.5**. The workshop was checked with the macOS arm64 post1 distribution.
2. Open `psychopy_bridge_tutorial/starter.psyexp` in Builder. Keep the adjacent Python and JSON files together.
3. Click **Run**. Press **Space** to arm the task, then **5** to simulate a scanner start on your keyboard.
4. Report the grating tilt using **1** for left and **2** for right. **Escape** ends a run and saves partial records.
5. Open the new folder under `psychopy_bridge_tutorial/data/`. Read `trials.tsv` alongside `inputs.tsv`.

The default participant ID is 000. Change it in Builder's Experiment Settings → Experiment info. Odd participant IDs reverse the response mapping; the instruction screen displays the assigned keys. Run `check_keys.py` separately in PsychoPy Coder to observe the installed input names. At the scanner, replace the local key names in `hardware.json` with the names returned by the installed interface. A keyboard simulation does not test scanner synchronization or physical stimulus timing.

## What the experiment compares

The participant reports left or right tilt at high or low contrast. Size, spatial frequency, response window and tilt counts are held constant across contrast conditions. The intended fMRI contrast is low minus high, with fixation as an implicit baseline. Interpret behavioral differences before assigning a psychological meaning to a BOLD difference.

There are 32 trials, balanced across contrast and tilt, in a 176-second schedule. Gratings last 1 second; the first response within 1.5 seconds of the recorded onset flip is scored. Early and extra inputs are retained. Missing responses have `n/a` values. This short run is a teaching example, not a power calculation.

## Make one change and predict its effect

In `task.json`, change `response_window_s` from 1.5 to 0.5. Predict the effect on missing responses and the RT distribution. Run with volunteer responses, inspect the saved rows, and discuss whether the shorter deadline changes the question. Restore the original value before comparing another change.

## Where to edit

| File             | Purpose                                                     |
| ---------------- | ----------------------------------------------------------- |
| `starter.psyexp` | Builder Flow, Routines, Text and Grating components         |
| `starter.py`     | Python generated by Builder; regenerate after Builder edits |
| `task.json`      | Experimental conditions, durations and schedule             |
| `hardware.json`  | Trigger key, response keys and expected pulse interval      |
| `trial_core.py`  | Schedule, input decisions and response scoring              |
| `run_support.py` | One keyboard collector and buffered output                  |

Builder reads the schedule generated from `task.json` at the start of each run. The schedule is saved with that run. There is no separate manually maintained conditions table or standalone implementation.

## Read the saved data

`trials.tsv` contains the planned onset, onset and offset relative to the accepted start, raw flip times, response, RT and correctness. `response_window_complete` identifies whether an abort truncated a displayed trial’s response window. Flip times and input timestamps use the same task clock. `inputs.tsv` retains key-down time, retrieval time and event category, including pulse diagnostics. `frames.tsv` contains software callback intervals. `settings.json` and `schedule.tsv` retain what was run; `status.json` distinguishes complete, incomplete, timeout and aborted runs.

The first accepted trigger after arming defines task time zero. Later pulses are recorded without restarting the schedule. Event times must be related to the first volume stored in the corresponding imaging file before making BIDS events. A missing pulse is not proof of a missing image volume. Delayed frames and physical input/display latency require evaluation on the installed setup.

## For maintainers

Use Standalone's Python to run `build_starter.py` when changing the generated Builder source. The committed `.psyexp` is the student entry point. Ordinary Builder edits can be compiled with Builder's Write Python button.

Run the deterministic checks with `python -m unittest discover -s tests`. `BRIDGE_DEMO=1` injects synthetic arm, pulse and response events for software checks; it does not measure human behavior or hardware. `BRIDGE_ABORT_S=20` additionally injects a stop in demo mode. See `verification.md` for the checked environment and remaining physical checks.
